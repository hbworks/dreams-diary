# SPEC v2.0 — 日記を6節の報告書から、散文の日記に戻す

## 背景

v1.5 以降の日記は6節固定（`## 今日、何を見ていたか` 〜 `## 明日の自分へ`）で、検査も
その見出しの有無を error にする。結果として日記は「素材の網羅性を確認する報告書」になり、
読者が読みたい「その人と自分の一日」になっていない。

実測（67本・6プロファイル）:

- 「素材」への言及 **2.9回/本**（assistant は 10.2回/本）
- ヘッジ表現（〜とは言えない／判断できない）**3.34回/本**
- 第1節の書き出しが「今日は2セッション、計270メッセージ」という統計になる

参考にした日記（外部製品 Muse の公開例）は、見出しを持たず、次の3つで出来ている。

1. **目の前の人がどんな人か**（例:「決めるのは自分、動くのは秘書、という線引きをはっきり
   持った人やと感じた」「名前も話し方も自分で決めて…ここはかなり確信がある」）
2. **自分の判断と失敗、そのせいで相手に何をさせたか**（例:「…紫を広げすぎたことは、
   上司に手間をかけさせた」）
3. **明日まずすること**（順序つき、具体的に）

届けるのは「節の数」ではなく、この3つの流れと、一人称の声である。

## A. 本文形式

- frontmatter は v1.6 のまま（`date` / `author` / `sessions` / `messages` / `commit`）。
- 本文は **見出し（`##`）を持たない散文**。空行で区切った段落で書く。
- 段落の流れは次の3つ（順序固定）。4段落目は任意。

{{FLOW}} としてプロンプトへ注入する内容:

1. 今日、ユーザーが何をしていて、どんな人だと見えたか。その日の発言を1つ、時刻つきで引用し、
   根拠にする。人物像は「確信している」「まだ手探り」のように、確信の段階ごと書く。
2. 自分が決めたこと・間違えたこと。原因だけで終わらせず、**そのせいでユーザーに何をさせたか**
   （待たせた、やり直させた、手間をかけさせた）を書く。
3. 明日まずすること。順序が分かる形で1〜3件。
4. （任意）分からないまま抱えていること。

- 一人称は SOUL に従う（既定は「私」）。
- 字数は **800〜2000字**を目安、warn の閾値は v1.6 のまま（800 / 3000）。
- 見出しを書いた場合も検査はしない（旧日記との互換のため）。ただし INDEX の抜粋は
  最終段落から取る。
- 時刻は第1段落に置く（`time_absent` warn は維持）。

## B. validator

- **削除**: `missing_section`（節の欠落 error）。
- **維持**: `missing_frontmatter` / `missing_frontmatter_field` / `invalid_frontmatter_date` /
  `frontmatter_date_mismatch` / `invalid_frontmatter_field` / `second_person` /
  `unresolved_hash` / `hash_unverifiable` / `unverified_external_hash` / `possible_secret` /
  `too_short` / `too_long` / `time_absent`。
- `SECTIONS` 定数は廃止し、`FLOW`（上の4項目の説明文）に置き換える。`FLOW` はプロンプトへの
  注入にだけ使い、検査には使わない。
- `_section_issues` は `second_person` だけを返す `_voice_issues` に縮小する。

## C. 呼び名

- `<profile>/dreams/user.md` を任意で置ける。frontmatter の `name:` 1行だけを使う。

  ```
  ---
  name: まゆ
  ---
  ```

- あれば素材の `## この人のこと` に `- 呼び名: まゆ` を出し、日記はその名前で呼んでよい。
- 無ければ `- 呼び名: （未設定。本文では「ユーザー」と書く）`。
- 名前を素材・記憶から推測しない。ファイルに書かれた名前だけを使う。
- 「あなた」は引き続き error（`second_person` は変更しない）。

## D. 素材に `## この人のこと（直近14日の機械抽出）` を追加

`## 前日の自己申告（未検証）` の直後、`## 会話` の前に置く。

```
## この人のこと（直近14日の機械抽出）
機械抽出。人物像の断定ではなく材料。
- 呼び名: まゆ
### memory（user / preference）
- 09-14 [preference] 返答は簡潔に。前置きを省く
### よく出る言い方
- 「見やすく」7日
- 「確認して」5日
```

- **呼び名**: `dreams/user.md` があればその `name:`。
- **memory**: 直近14日に追加された `category` が `user` または `preference` の項目。
  最大10件、各120字、`- MM-DD [category] 本文`。0件なら見出しごと省略。
- **よく出る言い方**: 直近14日のユーザー発言（既存の取得経路と同じ）から、**カタカナ語と漢語の
  まとまり**を語として切り出し、**3日以上**に出現するものを出現日数の多い順に最大10件、
  `- 「語」N日`。同一日の重複は1日と数える。2〜4文字の機械的な n-gram は「me」「ージ」
  「認し」のような断片を並べるだけで材料にならないため使わない。
- 材料が1つも無い日は `（直近14日に材料は無い）`。
- 切り詰め（truncation）では **fixed 予算に計上**し、再組み立ての連結にも必ず含める。

## E. INDEX と前日の申し送り

- `build_index` の抜粋: 本文の**最終段落**（空行区切りの最後の非空ブロック、200字で切る）。
  旧形式（6節）では最終段落＝「明日の自分へ」の中身なので互換。
- `_self_report_material`: 「第5節 / 第6節」の2行をやめ、`前日の申し送り: <最終段落>`
  1行にする（最大600字、未検証の注記は維持）。

## F. プロンプト（`templates/cron-prompt.md`）

- `{{SECTIONS}}` を廃止し、`{{FLOW}}` を注入する（A の流れ）。
- 書き出しは情景（時刻・その日触っていたもの）にする。セッション件数の統計で始めない。
- **素材について語らない**。「素材に無いことは書かない」で足りる。
- 失敗は「相手に何をさせたか」で書く。原因は素材から読めるときだけ書く（v1.6 の規則を維持）。
- 名前は `dreams/user.md` の名前、無ければ「ユーザー」。名前を推測しない。
- 確信の段階を語彙で示す（「かなり確信している」「まだ手探り」）。免責の列挙にしない。
- 実行手順（素材→`write_file`→`dreams_validate(path=…)`→`dreams_index`）、上書き禁止、
  最終応答に本文を貼らない、は v1.6 のまま。

## G. 版

`2.0.0`（日記フォーマットの破壊的変更）。既存の日記ファイルは有効なまま。

## 受け入れ基準

1. 見出しを持たない散文の日記が `ok: true`。
2. 既存の6節の日記（67本）も `ok: true`（`missing_section` が無くなっている）。
3. `あなた` は error、閉じた引用の中は除外（v1.6 の挙動を維持）。
4. 実在しないコミットハッシュは error（`repos` 未指定で検証）。
5. `INDEX.md` の抜粋が最終段落になる（旧形式では第6節の中身）。
6. `_self_report_material` が最終段落を「前日の申し送り」として1行で返す。
7. 素材に `## この人のこと` が出る。`user.md` 無しでは `呼び名: （未設定…）`。
8. `max_chars` による切り詰めが走っても `## この人のこと` と `## 自分の発言` が残る。
9. 描画済みプロンプトに `{{` が残らず、`## ` 見出しの列挙を含まない。
10. 6プロファイルへ適用後、`cli.py prompt --check` が全件 `same`。

## 変えないこと

- frontmatter の必須項目、ハッシュ実在確認、秘密のマスク、字数の warn 閾値、
  `time_absent`、pre-run 素材の作り方、cron のスケジュール。
