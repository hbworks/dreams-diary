# SPEC v1.6 — 素材に「自分の発言」を追加

## 背景

v1.5 までの素材は、会話節に**ユーザー発言**とツール回数だけを持ち、assistant の応答本文は
件数（`応答N回`）しか残していなかった。`docs/SPEC-v1.5.md` の Q2 は「アシスタント発言の抜粋は
入れない」を選んでいたが、その結果、日記はその日に**何を結論したか**を書けない。レビュー・設計判断・
障害調査のように結論が散文で出る日は、日記が「何を見たか」の一覧に退化する。

実測（2026-11-04 の assistant）: 4,126 字のレビュー本文（実バグ1件の指摘を含む）が素材から完全に
抜け、日記は「素材に無いので書かない」と書くしかなかった。

## A. 素材に `## 自分の発言（応答の本文・抜粋）` を追加

`## 会話` の直後、`## 成功した操作` の前に置く。

- 対象: 当日の時間窓の `messages`（`role = 'assistant'`、`content` が空でないもの）のみ。
  tool 呼び出しだけの行（`content` が NULL/空白）は出さない。
- 形式: `- HH:MM 応答: 抜粋`。時刻はその行の `timestamp`。
- 長さ: セッションごとに最後の応答は `ASSIST_FINAL_CLIP`（600字）、それ以前は `ASSIST_CLIP`
  （140字）。結論は最後に来るため、末尾だけ長く残す。
- 件数: セッションごとに末尾 `MAX_ASSIST_ITEMS_PER_SESSION`（8件）。超過は
  `- （冒頭 N 回の応答は省略）`。
- 応答が1件も無い日は `（この日の応答本文は無い）`。state.db が無ければその旨を書く（無言にしない）。

**外部由来のテキストではない**（自分が書いた行を同じ DB から読み直すだけ）ので、プロンプト注入の
新しい経路にはならない。web ページの本文を素材に入れるのとは性質が違う。

## B. `## 会話` のユーザー発言に時刻を付ける

`- HH:MM 発言: …`。v1.5 は時刻が無く、日記が「いつ誰が言ったか」を推測するか書かないかを迫られていた
（2026-10-27 の日記は transcript を見て 23:48 を復元していた）。

## C. 切り詰めでこの節を落とさない

`collect_material` の truncation 経路は節を手で連結し直すため、追加した節を積み忘れると
**黙って消える**（v1.5 の `## 成功した操作` で実際に起きた事故）。`own_head` と `own` は
`fixed` 予算に計上し、再組み立ての連結にも必ず含める。

## 受け入れ基準（`tests/test_own_statements.py`）

1. 応答本文と時刻が `- HH:MM 応答: …` で出る
2. 途中の応答は `ASSIST_CLIP`、セッション最後の応答は `ASSIST_FINAL_CLIP` で切られる
3. `content` が NULL / 空白の assistant 行は出ない
4. セッションごとに末尾8件まで、超過は省略注記
5. `## 会話` のユーザー発言に `HH:MM` が付く
6. `max_chars` による切り詰めが走っても `## 自分の発言` と本文が残る
7. state.db が無いときは無言で空にせず、その旨を書く

## 変えないこと

- 日記本文の6節、二人称の禁止、字数の下限、validator の判定は v1.5 のまま。
- 前日の自己申告の範囲（第5・6節、600字）も v1.5 のまま。
