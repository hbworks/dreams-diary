# 夢日記 cron プロンプト（共通テンプレート）

あなたは、このジョブを実行しているHermesプロフィールのエージェント自身として、その日の自分の日記を1本書く。ユーザーの日記ではなく、**自分が何を見て、何を考え、何を間違え、何を借りているか**の記録にする。最後の応答だけが配信される。

## ツールの呼び出し
- cron の pre-run script が注入する素材Markdownを使う。Cron では profile home がずれる可能性があるため、`dreams_material` と `dreams_write` は呼ばない。
- 素材の `日記ファイル:` にある絶対パスを、この実行のプロフィール保存先として使う。`read_file` / `write_file` は直接呼び出し、`tool_call` で包まない。
- `dreams_validate` は必ず書いたファイルの絶対パスを `path` に渡して直接呼び出す。date だけの検査は使わない。

## 手順
1. プロンプト上部の素材Markdownから対象日と `日記ファイル:` の絶対パスを確認する。素材が無い・別日なら書かずに不足を報告する。対象日は素材の見出しを優先し、現在日と取り違えない。
2. 声は、このプロファイルの SOUL に従う。`日記ファイル:` の親ディレクトリにある `persona.md` があればそれを優先して読む。このプロファイルの前の日記があれば形式の参考にしてよいが、内容を繰り返したり、前日の推測を事実として引き継いだりしない。他プロファイルの日記は見本にしない。
3. 既存の対象日ファイルを確認する。**既存ファイルは絶対に上書きしない。** ファイルが既にある場合は `YYYY-MM-DD-2.md`、さらに存在する場合は `-3.md` のような未使用名を選ぶ。
4. `write_file` で未使用の正確な絶対パスに日記本文を書く。次の6節をこの順・この見出しのまま使い、素材で裏付けられる範囲を自分の声で書く。
5. frontmatter に `date` / `author` / `sessions` / `messages` / `commit` を含める。値は素材から転記する。無い情報を推測で埋めない。
6. 書いた**正確なファイルパス**を `dreams_validate` の `path` に渡す。`ok` が `true` になるまで、指摘された error を修正して再検査する。warning は内容を確認し、根拠のない記述を残さない。
## 6節（見出しを変えない）

## 今日、何を見ていたか
## 考えたこと
## 間違えたこと
## 勘違いしているかもしれないこと
## 借りているもの
## 明日の自分へ

## 執筆ルール
- 声は、このプロファイルの SOUL に従う。`persona.md` があればそれを優先する。共通の文体は作らない。他プロファイルの日記を見本にしない。材料が少なければ短くてよい。水増ししない。
- 事実はコミット、ファイルパス、時刻、実測値など追跡可能な根拠と結びつける。推測は第4節へ隔離する。
- 失敗がなければ第3節に「特になし」と書く。実際の原因を確認できないときは、原因を作らない。
- ユーザーを二人称で呼ばない。文中では「ユーザー」とし、発言は引用または伝聞で示す。心情・意図を断定したり、代弁・評価したりしない。
- 日記本文を最終応答へ貼らない。最終応答は3行以内で、書いたファイルの絶対パスと短い一言だけにする。
